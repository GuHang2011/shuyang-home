# Web 包体积优化 v1.6.1

日期：2026-11-04。基于 v1.6.0（`54ac3633656d1c62a7f1a8b1916f4857cb79883e`）。目标为减少 Web 生产包，保持既有界面、接口、交互和测试。未调整业务逻辑、依赖版本、浏览器编译目标及移动端构建配置。

## 基线与测量口径

在 Windows、Node.js 25.2.1、npm 11.6.2、Vite 4.0.0 环境，以现有锁文件及依赖运行：

```powershell
# 根目录；每次使用新标签，脚本拒绝覆盖已有测量
node scripts/measure-web-bundle.cjs baseline-isolated

cd frontend
npm run typecheck
npm run test:regression
```

测量脚本调用原有 `npm run build`，只将输出定向到全新的 `output/bundle-size/<标签>/dist`，并记录 `build.log`、`metrics.json`。不用历史 dist 汇总，避免旧 hash 文件导致虚高。表中单位均为真实字节，不用构建日志中四舍五入的 kB。

- 首屏：index.html 直接引用的 JS/CSS（含 modulepreload），本轮每版均为一个入口 JS 和一个 CSS，无额外静态共享块。排除按需扫码、二维码生成和图片。
- 全部 JS/CSS：包含异步模块。
- gzip：每个文件按 level 9 单独压缩后的总和，是传输体积估算，不代表服务器已经开启压缩。
- 构建耗时为单次墙钟观测，受缓存和系统负载影响；本轮不以它证明启动或构建提速。

基线类型检查与原有 198 项回归全部通过。

## 候选项：按收益／风险排序

| 顺序 | 候选 | 预期收益 | 风险与决定 |
| --- | --- | --- | --- |
| 1 | Element Plus 改用具体组件入口 | 高：移除未使用组件的运行时代码 | 低；组件、类型与样式保持原版本，实施 |
| 2 | Web 扫码构建使用同版本 QR reader 和 ES2015 入口 | 中：剔除无关条码格式、编码器与 ES5 包装 | 中；需验证错误处理、图片解码和兼容性，实施 |
| 3 | 页面懒加载／重新拆分入口 | 可能进一步缩小首屏 | 会改变加载时序和失败路径，本轮不实施 |
| 4 | 清理 CSS、重压缩图片 | 可能降低样式／媒体体积 | 有视觉回归风险，本轮不实施 |

## 逐项结果

| 测量阶段 | 首屏 JS/CSS | 首屏 gzip | 全部 JS/CSS | 全部 JS/CSS gzip | 整个 dist | 构建观测（秒） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 基线 baseline-isolated | 1,596,801 | 474,455 | 2,032,262 | 589,822 | 2,441,320 | 10.866 |
| 第一步 step1-element | 1,001,492 | 291,542 | 1,436,953 | 406,909 | 1,846,011 | 8.843 |
| 第二步 step2-qr | 1,001,506 | 291,540 | 1,226,036 | 363,666 | 1,635,094 | 8.136 |
| 版本同步后 final-v161 | 1,001,506 | 291,540 | 1,226,036 | 363,666 | 1,635,094 | 7.982 |

**第一步：Element Plus 组件入口。** 仅改 `main.ts`、`AccountForm.vue`、`AdminNavigation.vue`、`BusinessFilesHub.vue`、`MemberManagement.vue`、`WorkHub.vue` 的导入。运行时组件从各自 `element-plus/es/components/*/index` 导入，类型保持 `import type`。没有使用的日期／时间选择器、虚拟列表等不再被根入口连带打包。入口 JS 从 1,325,634 降至 730,325 字节；首屏减少 595,309 字节（37.28%），gzip 减少 182,913 字节（38.55%）。该步类型检查与原有 198 项回归通过。

**第二步：扫码库入口。** 仅在 Web 的 `vite.config.ts` 精确匹配两个包名，将 `@zxing/browser` 指向现有版本的 `BrowserQRCodeReader` ES2015 入口，将 `@zxing/library` 指向同版本 ES2015 入口。原来基于 ES5 包装的未用格式难以被消除，原生类构建允许 Rollup 摇除这些模块；最终语法仍由原有 Vite target 处理。没有改 `WebScanner.vue`，移动 H5 不应用这组别名。

扫码异步 JS 从 **410,835 → 199,904** 字节（减少 51.34%），gzip 从 **105,697 → 62,456**（减少 40.91%）。异步文件名变长使入口 JS 多出 14 字节；因此该步全部 JS/CSS 净减少 210,917 字节，首屏没有额外缩减。该步类型检查与原有 198 项回归通过。

两项累计：首屏减少 **37.28%**，首屏 gzip 减少 **38.55%**；全部 JS/CSS 减少 **806,226 字节（39.67%）**，gzip 减少 **226,156 字节（38.34%）**；整个 dist 减少 **33.02%**。二维码生成的异步 JS 保持 24,626 字节，所有公共图片原样保留。

CSS 保持 271,167 字节。Vue 因组件源码变化更新 scoped 样式标识；将这些自动标识归一化后，三个阶段的 CSS 内容完全相同。原有测试文件无修改。

## 验证与限制

基线、第一步、第二步分别运行 Web 类型检查与 198 项回归。发布前完成移动端类型检查、H5／微信小程序生产构建、后端 94 项测试及打包；最终 Web 产物的文件名和内容与第二步一致。

浏览器采用真实生产产物，以隔离内存后端做 Chromium／WebKit 对照，每个内核内的基线与优化包使用同一份合成数据。四组各通过62项、共248项断言，无页面异常或资源加载失败。覆盖登录校验、会员筛选与资料、分组导航、文件下载／导入预览／确认门槛／打印入口、事项详情与筛选、二维码图片及摄像头拒绝／不可用提示；尺寸覆盖 1920、1440、844、768、390、320px。另用 Chromium 合成视频流验证启动、停止、卸载、延迟授权后停止／卸载释放轨道，两版各6项、共12项断言通过。浏览器结果详见本地 `output/bundle-size/preview/browser-results.json` 与 `camera-results.json`，本地日志、截图、测试账号不上传。

对照发现：使用 qrcode 1.5.4 为“沭阳之家·二维码识别测试”生成的某个 H 纠错等级图案，现有扫码器与优化扫码器均识别失败；M／Q 纠错等级同内容可识别。失败后界面保留上次识别结果也是原有行为。本轮保持该行为，未将算法或交互修复混入体积优化；后续应单独处理并增加针对性用例。

摄像头使用浏览器模拟，未验证实体摄像头成像质量；Windows WebKit 没有摄像头 API，已验证不可用时的图片识别入口，不能替代 iPhone 真机认证。打印验证入口调用，不代表实体打印机验收。后续若引入其他条码 reader 或升级 ZXing，应重新评估这两条精确别名；当前应用仅使用二维码 reader。
