事项涵盖入会申请、活动报名、互助、订单、资源交换、联系方式交换、众筹认领、活动申请、论坛主题／回帖、资源发布、广告和众筹项目。操作仍经过原业务接口，聚合页不会直接改写订单或审核状态。

普通会员仅查看本人的事项。待审核会员仅查看本人的入会进度。管理者只见原角色有权处理的内容，组织者不能通过总览读取他人订单，版主只见已分配板块。论坛审核引导进入原论坛查看图片、语音和上下文后处理。

## 通知与互助规则

- 业务通知是站内持久记录，覆盖入会及内容审核、报名／签到、活动取消／集合点调整、订单履约、资源／联系方式交换和认领进度变化。公共公告与原聊天继续独立使用。
- 通知和业务写入同一事务，业务失败时一并回滚。无状态变化的重复保存不重复提醒；活动取消只产生一次对应通知。文件导入造成的报名变化也会生成通知。
- 已读与办完相互独立。批量已读提交上次查询的序号上限，新到达的通知不会被一起清掉；原详情不可用时保留未读，可主动标记已读。
- 通知只保存通用说明及站内目标编号，打开目标时重新鉴权。不会把完整私有正文复制到通知中。
- 通知摘要在前台每15秒刷新，后台停止请求；下次进入仍能读取。首次升级不补发历史业务通知，原有事项可以直接汇总查看。
- 互助有效期为7、30或90天；旧记录未设置有效期的保持原状态。默认互助广场展示仍有效的“还需要帮助／处理中”信息，可切换查看已解决和已过期记录。
- 已公开互助修改后进入草稿审核，旧正文及旧联系信息继续公开；新草稿、退回说明及历史版本不向其他会员或访客泄漏。初审退回内容可以修改重提。
- 更新进度与审核携带编辑版本；另一端已修改时返回冲突提示。已解决重新打开需填写至少5字原因；过期信息要修改续期并审核；关闭与已解决不同，关闭后不能绕过审核重新公开。

## 发现并修复的问题

| 问题 | 处理结果 | 验证方式 |
| --- | --- | --- |
| 事项跳到签到页只传活动编号和标题，导致网页日期转换异常 | 补齐起止时间、地点，保持原签到接口与定位规则 | 后端目标字段断言；Chromium、WebKit、移动H5实际跳转 |
| 论坛回帖事项缺少主题编号，管理跳转缺少模式信息 | 返回主题编号和管理标记，精确定位原论坛记录 | 回帖上下文与板块撤权测试；两端类型与构建检查 |
| 过期互助仍显示“处理中／重新打开”等无法提交的按钮 | 仅提供办结和修改续期操作 | 过期状态与操作集集成测试 |
| 关联活动不存在会中断整个事项列表 | 保留报名记录并明确显示关联活动不可用，其他事项正常读取 | 关联记录移除集成测试 |
| 总览初次显示时“会员服务”已是默认分类，点击不会触发切换 | 同时处理分类点击事件，允许从总览直接进入会员与入会 | 类型检查；手工浏览器导航复核 |
| 新事项页的面包屑沿用个人中心，移动端我的互助缺少更新入口 | 使用当前页标题，并补齐手机端进度／修改入口 | 浏览器页面检查与移动H5流程 |

权限、重复提交、通知快照、弱网表单保留和旧响应隔离均作为实现约束加入测试，没有把正常业务限制当作缺陷解除。

## 交付边界

- 业务通知首版为站内消息，不包含短信、微信订阅消息或手机离线推送。
- 微信小程序已通过类型检查、协议场景测试和生产编译；微信容器、真实小程序、系统软键盘仍需真机验收。浏览器WebKit模拟不等于iPhone真机。
- 聚合接口失败显示错误并提供列表重试；缺失的关联活动单独显示不可用。本版没有增加独立模块服务或自动审批。
- 新版本增加通知序列及JSON业务字段，现有记录无需批量迁移。部署前按原规范备份数据；新草稿审核流程不由旧版识别，回退应结合备份和未处理草稿检查。
- 仅上传本轮代码、测试、文档和版本标签。原工作目录中并行任务的未提交修改保留；缓存、测试输出、运行时凭据及真实数据库均不上传。源码发布不等于生产部署。
