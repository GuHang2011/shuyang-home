# 启动与部署

## 1. 本地运行

要求 Node.js 18+、npm、JDK 与 Maven wrapper；当前改造在已有 Java 8 / Maven 缓存上验收。原工程目录名保持不变，应用名和数据库均已改为 `shuyang-home`。

项目根目录分别运行：

```powershell
.\Start-Backend.ps1 -Build
.\Start-Frontend.ps1
```

后端9999端口，前端8888端口；如机器限制脚本执行，可用 `powershell -ExecutionPolicy Bypass -File ...`。

首次启动提示设置管理员初始密码：至少12位、包含字母和数字。初始超级管理员账号为 `admin`，首次登录必须改密。然后在管理工作台审核老乡的自愿入会申请，发布公告与活动。请由超级管理员建立另一位可信超级管理员，避免管理员账号无法恢复。

如已存在数据库但尚未初始化管理员，使用 `Start-Backend.ps1 -InitializeAdmin`。初始化只在没有管理员时生效，不覆盖已有密码。普通会员忘记密码由管理员核实身份后重置；管理账号须由另一名超级管理员处理；新临时密码首次登录必须更改。

如9999被占用，在后端终端先设置 `$env:SHUYANG_PORT='19999'`；前端使用 `Start-Frontend.ps1 -BackendPort 19999`。

手机同一局域网可使用 `Start-Frontend.ps1 -Lan`，打开 `http://电脑局域网IP:8888`。生产环境需 HTTPS，开发服务器不用于公网。

## 2. 环境变量

| 变量 | 作用 / 默认值 |
| --- | --- |
| `SHUYANG_PORT` | 后端端口，默认9999 |
| `SHUYANG_ADMIN_PASSWORD` | 仅首次创建管理员，后续不覆盖 |
| `SHUYANG_DB_URL` | 默认 `jdbc:h2:file:./data/shuyang-home;DB_CLOSE_ON_EXIT=FALSE` |
| `SHUYANG_DB_USER` / `SHUYANG_DB_PASSWORD` | 数据库凭据 |
| `SHUYANG_DATA_KEY` | 可选 Base64 AES 密钥，加密JSON业务记录；不加密附件BLOB，部署时设置并独立保管 |
| `SHUYANG_ALLOWED_ORIGINS` | 跨域来源白名单，同源反向代理一般不必修改 |
| `VITE_API_PROXY_TARGET` | 开发前端代理目标，不写入生产网页 |
| `VITE_SHUYANG_API_URL` | uni-app 构建时的 HTTPS API 地址，以 `/api` 结尾 |

原 `ERP_*` 变量不再用于新系统。不要将原学生数据库路径配置为会员数据库。

数据密钥必须在持续运行中保持不变，换密钥没有自动重加密功能。Java 8 较早版本可能不支持 AES-256，可使用随机16字节密钥或升级运行时。用安全随机源生成，不能用口令代替。密钥丢失将无法恢复加密记录。

## 3. 构建与验证

后端：在 `backend` 执行 `mvnw.cmd clean package`（Linux 为 `./mvnw clean package`），输出 `target/shuyang-home-<版本号>.jar`，版本号读取根目录 `VERSION`。集成测试使用内存数据库，不写真实数据。版本更新流程见[版本发布规范](版本发布规范.md)。

网页：在 `frontend` 执行 `npm ci`、`npm run typecheck`、`npm run build`，发布 `dist` 文件夹。

多端：在 `frontend/mobile` 执行 `npm ci`、`npm run build:h5`、`npm run build:mp-weixin`，输出 `dist/build/h5` 和 `dist/build/mp-weixin`。网页管理工作台也适配手机，小程序侧提供会员流程。

## 4. 微信开发者工具与发布

1. 在 `mobile/src/manifest.json` 的 `mp-weixin.appid` 填写平台真实的小程序 AppID。空 AppID 构建会得到 `touristappid`，只能作开发检查，不代表可发布。
2. 将 `mobile/.env.example` 复制为 `mobile/.env.production.local`，把 `VITE_SHUYANG_API_URL` 改为真实 HTTPS 地址，例如 `https://members.example.com/api`。该地址会编译进客户端，不是密钥。
3. 在微信小程序管理后台配置对应的 `request`、`uploadFile`、`downloadFile` 合法域名、服务类目、隐私保护指引和所需备案。
4. 执行 `npm run build:mp-weixin`，开发者工具导入 `dist/build/mp-weixin`。保持 `urlCheck: true`；在有权的开发测试环境可按微信工具规则调试，正式验收使用真实域名。
5. 真机验证：登录／退出、入会和审核状态刷新、成员名录公开偏好、活动发起／报名及取消、广告申请与排期、投票、众筹认领／取消／交付、联系方式双向同意及撤销、互助／资源审核状态、私聊申请／发送／撤回／群聊退出／前后台未读、定位授权／拒绝与天气切换、长文本、日期时间选择器、字体、下拉刷新、断网提示和账号停用。
6. 审核通过后由平台账号上传发布。当前项目没有接入微信一键登录、微信手机号授权、微信支付、订阅消息；手机号为用户填写的登录账号，真实性由入会团队人工核实。

没有配置 API 地址时，小程序会明确显示服务未配置，不会使用虚构的成功数据。uni-app H5 本地开发默认通过 `/api` 代理访问后端。

广告与众筹没有支付SDK、支付商户号或在线收款流程；无需填写支付凭证。资金意向记录不能当作到账凭证。论坛入口开关位于 `frontend/shared/features.ts`，默认 `forumEnabled = true`；调整后需要重新构建网页和小程序，已有论坛API仍保留。

## 5. Linux 同源部署

生产改造前先升级至受维护的 JDK / Spring Boot，再在目标环境运行同一套验收。当前版本保留原旧框架，交付为可运行试点版本。

使用专用系统用户 `shuyang`，示例目录 `/opt/shuyang-home`，持久数据目录 `/var/lib/shuyang-home`，私有配置 `/etc/shuyang-home.env`，Web 根目录 `/var/www/shuyang-home`。分别部署后端 JAR 和网页 `dist` 内容。不要将整个工作区设为 Web 根目录；尤其不要暴露归档、数据库、日志和环境文件。

- `deploy/shuyang-home.service`：systemd样例；后端只监听127.0.0.1。将本次版本的JAR部署到 `/opt/shuyang-home/shuyang-home-<版本号>.jar`，并将 `shuyang-home.jar` 符号链接指向它，再重启服务；保留上一版本JAR便于回退。每次升级确认链接版本与 `VERSION` 一致。
- `deploy/nginx.conf.example`：HTTPS、SPA、API反向代理样例。`/api/` 必须转发到后端 `/`，去掉前缀。
- `deploy/shuyang-home.env.example`：环境变量样例；填写独立随机密码与密钥，并限制环境文件权限。

申请真实 TLS 证书后替换样例域名与证书路径，执行 `nginx -t` 后 reload。不要上传本地测试账号、`.cache`、`archives` 或 `output`。

## 6. 数据与备份

默认数据库位于后端工作目录 `data/shuyang-home.mv.db`；Linux示例使用 `/var/lib/shuyang-home/shuyang-home.mv.db`。所有会员、会话、活动、订单、日志及附件保存于 `syh_*` 表，附件二进制在同库 `syh_attachment` 表。当前 H2 + 全局事务写锁支持单实例，不能直接开启多个服务进程写同一库；容量扩大需数据库与分页方案专项改造。

备份顺序：停止后端服务，确认进程退出，复制数据库文件及匹配版本配置到独立受限存储，然后启动服务。加密密钥与备份分开保管。不要运行中直接复制 H2 文件，也不要把原辅导员恢复脚本用于此系统。

恢复顺序：先在新的空目录复制备份数据库，配置原始数据密钥与匹配应用版本，在隔离端口启动；检查会员数、报名、审核记录后再切换。保留当前数据副本，避免直接覆盖。定期演练恢复和账号处理流程。

## 7. 隔离演示

`scripts/start-preview.ps1` 启动只监听本机的验收环境：网页18888、uni-app H5 18890、API 19999，数据库在内存中，重启即清空。随机管理员初始密码仅保存在 `.cache/membership-preview/runtime.json`；这是临时验收配置，不是正式账号。

停止使用 `scripts/stop-preview.ps1`，脚本会核对进程命令行后停止对应预览进程。`scripts/browser-*.js` 和 `prepare-browser-fixture.py` 使用明确标识的测试账号与信息，只可用于该隔离环境，不可运行于生产。

## 8. 定位与开源天气 API

使用 [Open-Meteo](https://open-meteo.com/) 的开源预报服务和城市查询，无需API Key。当前固定上游为 `https://api.open-meteo.com/v1/forecast` 和 `https://geocoding-api.open-meteo.com/v1/search`，服务器需允许这两个HTTPS出站域名；客户端只访问本项目API，不直接请求上游。公开免费端点适用于非商业使用且有调用额度，正式运营前核对官方 [使用条款](https://open-meteo.com/en/terms)、额度及广告运营是否符合条件；超出适用范围时使用相应方案或自托管服务。

接口为 `GET /weather?latitude=31.30&longitude=120.60` 和 `GET /weather/cities?name=Shuyang`；经同源代理时添加 `/api`。后端连接超时4秒、读取超时6秒，最多256项、每项10分钟缓存，并有限流。页面保留Open-Meteo数据来源及北京时间；服务失败显示错误和重试，不显示虚构天气。

用户点击“使用我的位置”后才请求授权。浏览器定位要求HTTPS或localhost；局域网普通HTTP可能不支持，仍可手动选城。小程序声明 `scope.userLocation` 与 `requiredPrivateInfos: ["getLocation"]`，使用WGS84坐标；正式AppID需在微信后台满足定位接口的类目、隐私声明与接口开通要求。未获授权或能力未开通时保留手动选城，需真机验证。客户端与后端都将经纬度保留两位小数，不写入会员资料、审计记录或持久数据库，只用于天气请求和短期内存缓存。上游会接收天气查询坐标；部署代理日志应避免记录该接口的查询参数。

2026-10-28更新：中文短名称优先查询完整市名，再尝试原名与县／区名称；带“市”的名称无结果时也尝试简称。依据地名类型、行政区划与人口过滤同名村镇和机场，展示上游已有的省、市、区县层级，保留原始坐标。GeoNames把江苏淮安市标记为PPL，因此不能仅按PPLA过滤；“淮安”现可搜到江苏淮安市。沭阳目前缺少上游中文县级条目，搜索“沭阳／沭阳县／Shuyang”复用平台既有家乡快捷地点（34.13,118.79），标注江苏省／宿迁市。此检索依赖上游数据完整性，不承诺全国行政区划完整覆盖。

新增 `GET /weather/network-location`：只在用户主动点击定位时调用。设备失败、精度未知或报告误差超过5公里时尝试网络定位，也可直接点击“网络定位”。使用 [ipwho.is](https://ipwhois.io/documentation) 的公开HTTPS接口估算公网出口城市；这是第三方IP定位服务，不能等同于开源的Open-Meteo或精确GPS。需要允许服务器访问 `https://ipwho.is`，客户端仍只访问本站API，小程序无需额外配置该上游域名。免费端点存在额度与用途限制，正式运营前核对服务商条款。

网络定位取 `HttpServletRequest.getRemoteAddr()`，不接受客户端传入IP或上游URL。现有Tomcat配置仅信任本机代理，Nginx覆盖 `X-Forwarded-For`；生产环境应限制后端仅由可信反向代理访问。公网地址缺失、私网地址、上游失败或无有效城市时明确提示手动选城，不能把服务器出口当成访客位置。`SHUYANG_WEATHER_LOCAL_NETWORK` 默认false，仅本机隔离预览脚本将其设为true，此时localhost使用本机网络出口估算，部署时不要启用。网络结果内存缓存10分钟，不写数据库；返回值不含原始IP、运营商信息。页面明确标记“网络估算”，VPN、代理或移动运营商可能使城市有偏差。设备、网络定位只用于天气，活动签到仍使用原有设备定位和精度校验。

## 9. 站内聊天与容量边界

当前提供文字、图片和常用文件私聊与群聊，前台会话每4秒刷新、未读数每6秒刷新；页面在后台时不自动将新消息标为已读。暂无WebSocket、离线推送、语音和视频通话。私聊双方同意后才能继续发送，不自动公开手机号；群聊自愿加入，加入后可查看已有群记录，退出后不能读取。管理员不能越权读取私聊，审计不保存聊天正文。

每条消息最多2000字，每次历史请求50条；消息编号幂等、两分钟内可撤回。当前单实例H2与扫描式记录检索适合小规模试点，扩大使用前应增加数据库索引、服务端分页、消息保留策略与推送方案，并做并发容量测试。

## 10. 交付包

完成构建后执行 `scripts/package-release.ps1 -Name shuyang-home-20261028-r4`，生成 `release` 下同名目录和ZIP，内含后端、网页、H5、小程序构建、文档和部署样例，并附 `SHA256SUMS`。小程序包没有真实AppID及生产API地址，配置后需要重新构建。发布包不含业务数据库、测试账号、缓存或原辅导员归档。

## 11. 相册、附件、二维码和地点签到

相册由组织者/管理员创建、上传及发布，普通会员在H5和小程序浏览。提供的Alltuu原相册目前返回403，保留链接入口；未导入原照片。小程序对外部相册采用复制链接，不假设外部web-view域名已获得授权。

图片允许JPG/PNG，最大8MB、2000万像素，后端重编码移除元数据。聊天文件允许PDF/TXT/DOCX/XLSX/PPTX/ZIP，最大15MB；文件校验不是病毒检测。上传接口单独允许16MB请求，参见Nginx样例。试点限额为每用户滚动24小时100MB、总计1GB；未绑定附件超过24小时在后续上传时清理。附件存储在数据库，备份必须包含同一数据库；现有AES记录加密不覆盖BLOB，应使用受限目录、加密磁盘与加密备份。

下载每次校验成员/发布状态/撤回状态，不在URL带登录令牌。客户端撤回不能收回接收者已另存的文件。退出群聊后服务端拒绝继续下载该群附件。

H5与桌面使用浏览器摄像头、原生文件选择框和按需加载的ZXing识别二维码；小程序使用uni.scanCode。摄像头需要HTTPS或localhost，拒绝后仍可选图识码。仅识别本站活动签到格式，确认后才进入签到，二维码不会自动打开陌生链接。暂不支持纸质文档扫描或OCR。

组织者在响应式网页中设置WGS84签到点、50–2000米半径及有效窗口，可生成5分钟签到码；重新生成使旧码失效。签到仍需会员报名、活动开放、有效时间、精度及距离符合要求。保存签到时间和距离，不保存会员原始坐标；设备上报位置不构成防伪定位保证，异常时由现场组织者处理。志愿时长另行核定。

## 12. 权限与特产订单

超级管理员维护管理角色；普通管理员处理运营、普通会员停启与密码重置，不能任免管理员。志愿组织者处理活动与内容；版主只在分配的论坛板块审核、隐藏/恢复、删除、禁言/移出/恢复。最后一个有效超级管理员不能被降权或停用。论坛公开内容仍可由访客浏览，板块移出不等同私密板块隔离。

特产商品由管理员在响应式网页维护，H5和小程序提供浏览、下单、取消、收货。下单原子扣库存，请求编号防止重试重复订单；取消只归还一次。库存版本号防止旧编辑覆盖新订单扣减。订单人工确认后登记线下结算、发货或自提，会员实际收货后确认。已结算订单取消须先由管理员核实线下退款，不接入在线支付。上线前填真实商品图、供货商、售后与履约联系信息。

移动端重点交付为Android/iPhone H5及微信小程序，无独立APK/IPA。真实微信AppID、隐私声明、定位能力、upload/download域名和摄像头/相册授权需在真机验收。

## 13. 论坛语音

论坛新增语音附件，MP3／M4A／WAV最大10MB；与现有上传共用16MB请求限制、会员额度及私有BLOB存储。附件通过上传者身份绑定单条帖子或回复，每次读取核验审核状态、父话题、板块限制及黑名单。小程序通过downloadFile获取授权临时文件再播放，不把登录令牌放入音频URL。当前支持选择已有录音文件，不提供麦克风直接录音或转写。详见《论坛语音》。
