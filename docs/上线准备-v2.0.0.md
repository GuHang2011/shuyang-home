# v2.0.0 上线准备

本次交付是可部署的单实例安装包。当前尚未提供正式服务器、域名与微信 AppID，因此 GitHub Pages 仍是独立演示，真实会员服务和微信小程序尚未上线。

## 本轮修复

| 原问题 | 处理 |
| --- | --- |
| Java 8 / Spring Boot 2.3 运行基础过旧 | 升级为 JDK 21、Spring Boot 4.1.2、Jackson 3、H2 2.4.240，迁移 Jakarta 接口并运行业务回归 |
| 密钥、数据库密码或域名未配置也能启动 | `prod` 模式在打开数据库前拒绝缺失值、样例占位符、内存数据库、非 HTTPS 来源和非本机监听 |
| 空库可能没有可登录管理员 | 正式环境首次启动要求设置初始管理员密码，首次登录继续强制改密 |
| 健康检查只返回固定成功 | `/api/health` 检查数据库，故障返回 503，不返回数据库路径或错误详情 |
| H2 默认延迟写入，进程立即退出时可能丢失刚确认的修改 | 生产连接设置 `WRITE_DELAY 0`，已验证改密与审核后的停机备份恢复 |
| 2MB 表格被 Nginx 的 64KB 限制拦截 | 导入接口单独允许 3MB JSON 请求，照片／附件仍单独允许 16MB |
| 更新后旧页面缓存、缺失 JS 被返回成 HTML | 页面禁止缓存，带哈希的资源长期缓存，缺失资源返回 404 |
| H5 放在子目录时资源地址错误 | 支持同域 `/mobile/`，网页管理端仍在根目录 |
| 网页断网显示英文底层错误 | 改为中文网络重试提示 |
| 打包时可能混入旧构建或演示产物 | Web、H5、小程序写入构建版本，打包核对版本并拒绝演示构建 |

部署包包含后端 JAR、网页、H5、小程序开发构建、部署模板、文档、私有配置生成工具和 HTTPS 部署检查工具。没有通用生产账号密码，没有真实数据库或密钥。

## 首次部署路径

建议先用一台 Linux 服务器试运行，Ubuntu 24.04 LTS、2 核 / 4GB 内存 / 40GB 起步作为采购参考；这不是已验证的承载人数。照片、文件都写入数据库，需按使用量预留磁盘。当前全局写锁与记录检索按单实例设计，扩大规模前需实测并发并改造分页和数据索引。

1. 准备域名、HTTPS 证书；内地服务器按服务商要求完成域名备案。安全组只放行网站端口与受限管理入口，9999 不对公网开放。
2. 安装受维护的 JDK 21、Nginx、Python 3.9+。安装包可直接运行，服务器不需要 Node.js 或 Maven；只有重新编译才需要它们。
3. 下载并解压 `shuyang-home-v2.0.0.zip`，在包目录执行 `sha256sum -c SHA256SUMS`。保持包目录名不变，以便核对版本。
4. 创建专用服务用户和目录，再部署程序。以下命令在解压后的包目录运行：

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin shuyang
sudo install -d -o root -g root -m 755 /opt/shuyang-home /var/www/shuyang-home
sudo install -d -o shuyang -g shuyang -m 700 /var/lib/shuyang-home
sudo install -m 644 backend/shuyang-home-2.0.0.jar /opt/shuyang-home/
sudo ln -sfn shuyang-home-2.0.0.jar /opt/shuyang-home/shuyang-home.jar
sudo cp -a web/. /var/www/shuyang-home/
sudo install -d -m 755 /var/www/shuyang-home/mobile
sudo cp -a mobile-h5/. /var/www/shuyang-home/mobile/
```

5. 生成私有配置。把下面的域名替换为自己的真实域名；工具拒绝样例域名、不会覆盖已有文件，也不会向终端打印密码和密钥：

```bash
sudo python3 tools/create-production-config.py \
  --domain members.your-domain.cn --output /etc/shuyang-home.env
sudo chmod 600 /etc/shuyang-home.env
sudoedit /etc/shuyang-home.env
```

仅在服务器本机读取初始 `SHUYANG_ADMIN_PASSWORD`，妥善保存 `SHUYANG_DB_PASSWORD` 和 `SHUYANG_DATA_KEY`。**已经存在数据时不能重新生成这两个值**。生成工具仅供首次安装，原密钥需独立保管。

6. 安装服务并检查本机后端：

```bash
sudo install -m 644 config/shuyang-home.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now shuyang-home
curl --fail http://127.0.0.1:9999/health
```

7. 将 `config/nginx.conf.example` 放入 Nginx 的 `http` 配置范围（Ubuntu 通常为 `sites-available` 并链接到 `sites-enabled`），替换全部样例域名、证书路径。执行 `sudo nginx -t`，通过后再 reload。Nginx 已覆盖客户端传入的代理地址头；不要直接在其前面再加未经配置的 CDN 代理。
8. 在包目录运行只读验收：

```bash
python3 tools/check-deployment.py https://members.your-domain.cn --mobile
```

检查网页和 H5 入口及脚本、数据库健康、未登录接口权限、缓存策略和演示脚本隔离。它不会创建会员、修改资料或发送消息。工具通过仍需完成下文的真实业务验收。

9. 用 `admin` 和刚生成的初始密码登录，立即改密；然后清空环境文件里的 `SHUYANG_ADMIN_PASSWORD` 并重启。保留数据库密码和数据密钥不变。建立第二位可信超级管理员，确认普通管理员无法任免管理角色。

网页入口为 `https://自己的域名/`，手机 H5 为 `https://自己的域名/mobile/`。网页本身也适配手机。不要部署 `dist-demo`，不要把整个源码目录设为网站根目录。

## 备份、升级与回退

数据库文件为 `/var/lib/shuyang-home/shuyang-home.mv.db`，包含会员、帖子、会话、订单、审计及附件。备份时先停止服务并确认退出，复制数据库到受限备份存储，记录应用版本与 SHA256，再启动服务。运行中复制 H2 文件不算有效备份。数据密钥和匹配配置另行安全备份；附件 BLOB 不受记录 AES 加密覆盖，应使用加密磁盘或加密备份。

每次升级前保留旧 JAR、Web/H5 静态目录、配置和停机数据库备份。先在隔离目录／端口恢复备份，检查会员数量、论坛图片、活动报名和订单，再切换正式目录。发布静态资源时保留上一版本的 `assets` 文件，避免已打开页面按需加载旧资源失败；旧资源可在约定保留期后清理。

v2.0.0 的重要兼容变化：

- Java 8 无法运行新包，必须使用 JDK 21。
- H2 1.4.200 的 `.mv.db` 不能由 H2 2.4 直接打开。已有 v1 数据必须先停机备份，用旧版 H2 的 `org.h2.tools.Script` 导出 SQL，再用新版 `org.h2.tools.RunScript` 的 `-options FROM_1X` 导入**新目录的新库**。导出内容含敏感业务与附件，只能存放在受限目录。使用原数据密钥、原数据库密码，并核对恢复后的记录与附件；不要在原库上试迁移。
- 回退需同时恢复旧应用、旧配置和升级前的旧数据库副本；不能只切回旧 JAR 去读取新库。若上线后已有新写入，回退会丢失这些写入，应暂停操作并先制定数据保留方案。
- 新安装、没有需要保留的 v1 数据时，直接创建空库，不要导入演示数据。

## 微信与外部服务

微信目录名为 `wechat-dev-build`，不是已提交审核的正式小程序。填写真实 AppID，配置 HTTPS API、request/upload/download 合法域名及隐私指引后重新构建，再用 Android 和 iPhone 微信真机验收定位、扫码、拍照、上传及语音播放。

依赖检查：本轮 Web 的 `npm audit --omit=dev --registry=https://registry.npmjs.org` 返回 0 项。uni-app 包把部分构建工具也列为运行依赖，同一检查返回 37 项（20 high、10 moderate、7 low），涉及 Vite 开发服务、SSR、国际化与构建依赖。当前交付为静态 H5／小程序，不运行 SSR，不接受用户上传的模板或国际化词典，开发服务只绑定本机；这些限制减少暴露面，但不等于告警已修复。uni-app 当前 Vue 3 标签指向 alpha 版本，本轮未在上线前强行替换为 alpha 或执行会降级框架的 `audit fix --force`。小程序公开发布前应跟进稳定工具链补丁并在真机重新验收。

天气使用 Open-Meteo，网络估算使用 ipwho.is。免费服务的使用范围和额度需在运营前确认；有广告或销售业务时不要默认免费端点允许商业使用。AI 默认关闭，只有服务端配置供应商与密钥后才启用。广告人工审核、众筹意向认领、特产线下结算保持原约定，没有在线支付。

## 上线前最后一轮验收

- 用两部手机和不同账号验证：申请入会 → 审核 → 登录 → 高铁论坛发帖（照片／语音）→ 审核 → 他人可见；隐藏或删除后再次检查附件权限。
- 验证聊天申请、图片／文件发送与退出群聊后的访问限制；验证活动报名、签到拒绝定位时的提示；验证下单、取消及库存恢复。
- 核对真实组织联系人、隐私说明、活动日期、特产商品与履约说明。只发布已确认来源的高铁消息，不把规划消息当作开工或开通公告。
- 用目标设备检查 360px / 390px 手机宽度、三套常用主题、长标题、键盘弹起、断网与恢复；确认按钮可点、弹窗可关闭、没有横向溢出。
- 在目标服务器做一次停机备份及隔离恢复演练，检查磁盘余量和日志，再邀请少量真实会员试用。正式服务器和微信真机验收尚不能由本地测试替代。
