# 从老乡实际使用出发的功能设计

适用对象：在苏州生活、务工、创业的沭阳老乡、愿意提供帮助的会员、志愿团队及平台管理员。核心问题是“认识谁、需要什么、怎么参与、办到了没有”。平台公益、自愿参与，不设计付费会员、强制打卡或以活跃度划分身份高低。

## 本轮实现的完整流程

1. **入会与会员管理**：用户自行申请、管理员审核并说明退回原因；按姓名、手机号、地区、编号搜索并按状态筛选；查看资料、设置角色、启停账号、重置密码。普通会员资料默认不公开，名录公开与手机号公开分别选择。
2. **老乡论坛**：默认启用乡情闲聊、苏州生活、创业交流、家乡故事四个板块；发帖、楼层与引用回复、转发、本人待审记录、关闭回复；指定板块版主审核、隐藏、恢复、删帖、禁言与移出，会员可拉黑作者。
3. **资源互换**：明确填写“我能提供什么”“希望换到什么”，包括技能服务、闲置物品、场地设备、信息渠道。会员发起申请，资源主人接受／拒绝；一个资源一次只接受一项交换；双方分别确认完成，记录里展示各自确认状态，不使用虚假的交易成功提示。
4. **活动与志愿服务**：会员可提交活动计划，组织者审核通过后开放报名；报名、取消、人数上限、组织者签到、合理核定服务时长；个人中心汇总本人参与。活动的时间地点和取消状态全端一致。
5. **合作广告**：会员申请，人工审核，指定首页或活动页及展示日期；到期停止展示，申请人或组织者可以撤下。明确标识广告，不接支付。
6. **会员投票**：用于活动时间、主题、公共事务意见征集；组织者发起，审核会员一人一票，可单选或多选，只显示汇总，不公开个人选项。
7. **爱心众筹**：说明真实用途、执行安排、数量与期限，经审核公开；老乡认领物资、志愿服务或资金意向，个人中心可查记录并取消未交付认领。物资和服务由发起人核实交付；资金意向始终标注未收款，不在线收钱。
8. **联系方式交换**：从自愿公开的名录找到老乡，先说明来意，再由双方选择愿意分享的电话、微信或邮箱。接受前互不可见；可拒绝、取消或撤销后续展示。

9. **家里聊聊**：从会员名录申请私聊，对方接受后继续沟通；组织者建群，会员自愿加入／退出；文字、图片、文件、拍照入口、未读提醒、屏蔽恢复、两分钟内撤回。采用前台定时刷新，没有离线推送。
10. **出门天气**：首页查看苏州／沭阳与搜索城市天气；用户授权后可查当前位置，提供三日预报与带伞／添衣提示。使用Open-Meteo真实数据，不记录位置轨迹。

## 下一阶段优先设计

| 功能 | 真实使用场景与交互 | 权限与数据规则 | 优先级 |
| --- | --- | --- | --- |
| 业务通知盒子（与已实现聊天分开） | 入会通过、帖子审核、收到回帖、交换请求及对方确认时收到消息；点击直达原内容 | 仅收件人可读；已读与业务完成分开；不默认发短信或微信通知 | 高 |
| 收藏与关注 | 收藏稍后参加的活动、暂时用不到的资源、想继续看的帖子；关注话题更新 | 收藏默认私密；内容下架时展示不可用状态，不泄漏被隐藏正文 | 高 |
| 举报与帮助中心 | 对广告骚扰、虚假招聘、疑似诈骗发起举报；能看到受理和处理结果 | 举报人身份不向被举报人公开；组织者留处理依据；紧急情况提示联系正规救助渠道 | 高 |
| 会员技能与求助标签 | 例如水电维修、法律咨询、摄影、简历修改、创业经验；按“能帮什么”找到人 | 会员自愿填写，不把自填标签等同职业资质认证；联系电话另行授权 | 高 |
| 活动候补与提醒 | 满员可加入候补，退出产生名额后按顺序邀请；报名截止前提醒确认 | 候补不等于报名成功；设置确认期限；提醒仅站内，外部通道另行开通 | 高 |
| 交换记录关联聊天 | 在已实现私聊基础上附加交换记录入口，便于核对尺寸、时间、交接地点 | 关联前仍须双方接受私聊；不因关联业务而扩大聊天阅读权限 | 中 |
| 交换取消与纠纷协商 | 已接受的交换需要双方同意取消；一方停用、长期不回应时可申请平台协调 | 不允许管理员任意伪造双方完成；保留状态变更与处理理由 | 高 |
| 我的发布管理 | 退回内容可以修改后重新审核，已发布内容可暂停、更新、标记过期 | 实质修改后重新审核；不能借编辑绕过内容审核 | 高 |

## 三条完整用户旅程

- **新来苏州的老乡**：申请入会 → 审核 → 按地区和技能找老乡 → 阅读办事指南 → 报名一次线下活动 → 收藏常用联系人。
- **手里有闲置资源的会员**：发布“可提供＋想换到” → 审核 → 收到交换申请 → 双方确认交接安排 → 接受申请 → 各自确认交付 → 自愿感谢或评价。
- **志愿组织者**：查看待审队列 → 处理申请和内容 → 发布活动、分配志愿岗位 → 管理报名与候补 → 现场签到 → 核实服务时长 → 发布经授权的活动回顾。

## 判断功能是否有用

看真实入会完成率、审核耗时、活动出席率、互助／交换完成率和投诉处理时长；不靠虚构会员数、刷帖奖励、强制积分或排行榜制造活跃。每个新增功能都应有“用户怎么进入、结果怎么查看、出错如何撤回、谁有权限处理”的明确流程。

以上“下一阶段”和“扩展功能”是设计路线图，尚未全部实现；实际交付以验收记录为准。
