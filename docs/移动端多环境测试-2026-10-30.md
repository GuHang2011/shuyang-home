## 环境覆盖

| 环境 | CSS视口／像素比 | 附加条件 |

两内核均检查首页、商品列表、订单表单、订单提交按钮可达性、会员中心、聊天页面、聊天输入可达性、聊天发送按钮可达性。横向溢出对照设定屏宽检查，避免浏览器自动缩放掩盖问题；可见按钮高度至少44 CSS像素。输入与导航使用实际填充、触摸和滚动操作，聊天消息不实际发送。

异常测试覆盖null响应、502 HTML响应、断网保留登录、重连清理错误、订单失败保留地址和请求ID、摄像头拒绝／不可用降级、401清理会员信息。逻辑层另覆盖H5与微信小程序的超时、上传网关失败、附件下载过期、旧账号响应、后台轮询、弱网草稿和定位失败。

## 逐项修复

| 优先级 | 复现问题与用户影响 | 修复与验证 |
| --- | --- | --- |
| P1 | 移动接口返回null等非对象数据，回调异常导致加载不能正常结束 | `mobile/src/platform.ts` 校验响应类型并明确拒绝；两平台契约及浏览器重试通过 |
| P1 | 私有附件下载收到401后登录状态未同步失效 | 捕获请求时token，仅清理匹配的当前会话，补下载超时和错误文案；新账号不被旧401退出 |
| P1 | 弱网发送完成后，会清空发送等待期间输入的下一条草稿或新附件 | 只清理仍与本次发送内容匹配的草稿／附件；延迟响应回归通过 |
| P2 | 移动应用进入后台后仍持续请求未读数量 | 未读轮询结合前后台状态与document.hidden，恢复前台主动刷新 |
| P2 | 临时断网将已有未读角标清零 | 网络失败保留最后已知数量，身份改变时立即清理 |
| P2 | 轮询刷新尚未结束时离开聊天页，旧流程仍继续请求会话 | 异步刷新前后核对页面代次，卸载后不继续发请求 |
| P2 | 断网后重连成功，页面仍显示上一次全局错误 | 新一轮加载先清理旧错误；断网／重连浏览器用例通过 |
| P2 | Web订单原生输入控件在320～390px环境撑宽页面 | 补表单宽度约束、box-sizing、单列断点；两内核矩阵通过 |
| P2 | H5文本域宿主保留默认宽度，在320px表单中溢出 | 约束uni-input／uni-textarea宿主宽度，补滚动留白 |
| P1 | 390×420下Web聊天容器裁切输入区，发送按钮无法露出 | 增加聊天最小高度、保持标题高度、允许过高内容纵向滚动；检测实际遮挡后两内核均通过 |

前端检查重点是溢出、容器裁切、异步状态和平台接口；测试检查重点是异常恢复、生命周期和跨内核复现；产品检查重点是保留用户输入、清楚展示恢复入口，以及让关键提交操作始终可达。

## 真实设备验收范围

本次Windows WebKit没有mediaDevices接口，因此跳过该内核的权限拒绝模拟，并通过其原生“摄像头不可用→选择二维码图片”降级检查；Chromium通过模拟NotAllowedError验证权限拒绝。两者均未验证真实相机画面。

微信UA并非微信容器；Windows WebKit并非iOS Safari；390×420为键盘高度模拟，并未操作系统输入法。英文和纽约时区配置已用于页面流程，但未单独断言全部日期业务。横屏用例为独立初始布局，尚未验收真机旋转过程中的状态保持。

上线前还需在实际iPhone Safari、Android微信和微信小程序上验收相机／相册授权、GPS定位、系统键盘与旋转、安全区、后台恢复、附件打开与保存。微信小程序当前已通过uni接口模拟和构建检查，仍需开发者工具与真机运行确认。
