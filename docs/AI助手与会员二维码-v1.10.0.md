# AI 助手与电子会员卡二维码 · v1.10.0

## 使用方式

网页侧栏、会员中心以及手机首页／消息分类新增「AI 助手」。审核通过的会员可以查看使用指引、提问、起草活动邀请和互助信息，支持连续5轮对话、复制回复、新建对话与手动重试。未启用模型时显示配置提示；页面不自动请求付费模型。

发送前需确认将当前对话交由模型服务处理。只发送当前页面的文字问答和固定系统使用说明，不自动读取会员资料、订单、聊天、文件或页面业务数据。不会代替用户报名、审核、发布或发送消息。对话不保存到平台数据库或浏览器存储；离开页面或切换账号即清空。上游服务的数据保留政策由部署者选定的服务商决定。请勿输入密码、证件或他人联系方式，回复与草稿须核实后使用。

会员中心新增「会员身份码」。审核通过且已分配会员编号后，点击「出示会员二维码」即可生成有效10分钟的码，刷新立即撤销旧码。二维码包含随机短期凭证，不含姓名、手机或登录令牌。管理员及志愿组织者可在同一页面的「工作人员核验」扫码、选择二维码图片，或粘贴扫码内容并确认核验。结果仅返回姓名、会员编号、会员状态与核验时间，现场仍需核对持卡人。该码不执行活动签到、付款或账号登录；活动现场签到继续使用原流程。

账号停用、审核状态变化、要求修改初始密码、会员编号移除以及码到期时，服务端均拒绝核验。码在有效期内可重复核验，属于短期会员证明，不是实名证件或不可转借的凭证。页面倒计时只作提示，服务端时间和当前会员状态为最终依据。

## 配置真实 AI 服务

在服务器环境配置（参考 `deploy/shuyang-home.env.example`）填写：

```dotenv
SHUYANG_AI_ENABLED=true
SHUYANG_AI_BASE_URL=https://provider.example/v1
SHUYANG_AI_MODEL=your-provider-model-name
SHUYANG_AI_API_KEY=your-server-only-key
```

地址填写服务商的 API 前缀，系统追加 `/chat/completions`。生产服务必须为 HTTPS；本机协议验收允许 localhost／127.0.0.1／::1 的 HTTP。不允许地址内含账号密码、查询参数或片段，也不跟随上游重定向。保存环境配置后重启后端。不要将密钥放入 Vite 环境变量、前端页面、Git、截图或聊天。

当前兼容文本 Chat Completions 协议：Bearer 授权，`model`、交替 `messages`、`stream:false`、`max_tokens:1200`，读取 `choices[0].message.content`。须选用支持这些字段及 system 消息的模型。不同服务商的推理字段、多模态、流式输出及其他接口不在本版兼容范围。

单个问题最多2000字符，单次上下文最多9条、16000字符；回复最多6000字符，达到限制会提示。每位会员15分钟最多12次请求、同时1次；单进程最多4个模型请求。连接等待3秒、单次读取等待12秒，响应体另有12秒读取预算与256KB大小限制；前端 AI 请求最多等待45秒。错误不透传上游原文，不记录提问和回复。超时后只能手动重试，上游可能已处理并计费；多实例部署需另设统一额度管理。

## API

所有接口沿用 `/api` 反向代理及 `{code:0,data:...}` 响应。

| 接口 | 权限 | 输入／输出 |
| --- | --- | --- |
| `GET /ai/status` | 已审核会员 | available、demo、message、maxInput；不返回地址、模型或密钥 |
| `POST /ai/messages` | 已审核会员 | consent:true、messages:[{role,content}]；返回 content、demo、truncated |
| `POST /membership/card-code` | 有编号的已审核会员 | 无输入；返回随机 code、serverNow、expiresAt、demo |
| `POST /membership/verify-card` | 管理员／志愿组织者 | code；返回 name、memberNo、status、verifiedAt、demo |

不接受客户端 system／tool 消息、乱序对话、空内容和超限内容。未登录401，无权限403，输入错误400；助手未启用503，并发问题409，额度429，上游失败502，读取超时504。会员码失效或会员状态不可用409。生成会员码每人15分钟最多30次，核验每位工作人员最多120次。生成码是有副作用的刷新操作，客户端不自动重试；新请求会撤销旧码。没有引入数据库结构迁移，每位持卡人最多保留一个当前码的哈希记录与一个索引记录。

## 在线演示与验收

[GitHub Pages 体验版](https://guhang2011.github.io/shuyang-home/) 的 AI 只返回明确标注的本机固定示例，不调用外部模型。会员二维码也只核验同一浏览器内的虚构样例：会员生成后，切换演示管理员再扫码／粘贴核验；其他访客的浏览器不共享记录。

本版使用本机兼容协议服务器检查真实 HTTP 请求结构、授权头、错误、重定向、限额和超时；未配置真实模型密钥，不能据此保证某家付费模型已联调成功。微信小程序构建验证不替代真机扫码和画布验收。

自动测试命令：`node scripts/test-ai-assistant.cjs`、`node scripts/test-member-card.cjs`、`node scripts/test-demo-runtime.mjs`；均已纳入相应回归或发布流程。后端执行 `mvnw.cmd test`（新增 AiAssistantTests 和 MemberCardTests）。浏览器使用本机隔离内存数据库，覆盖宽屏、390／320px，检查示例标识、同意后发送、失败恢复、二维码识别与核验，以及旧码失效。

本轮结果：前端277项、演示数据层20项、后端170项通过；Chromium／Windows WebKit 各15项 Web/H5检查、Pages子路径演示19项检查通过，页面无运行异常。Web／移动端类型检查、Web／H5／小程序／后端与演示版构建通过。另单独确认 H5 发送成功后输入框清空。

验收发现并修复：原20秒请求超时不能覆盖较慢模型，单独延长 AI 请求等待；部分合法会员码的图片定位识别失败，增加单色二维码识别回退并恢复扫描器参数；手机320px宽度核验长编号溢出，新增结果换行及输入框尺寸约束。二维码图片实际经过浏览器识别与后端核验，未仅依赖绘制成功断言。
