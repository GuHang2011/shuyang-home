# 三角色测试与优化记录

日期：2026-10-30。按资深前端、测试工程师、产品经理三个视角完成代码检查、故障复现、修复和回归。本轮共处理下表12项问题，重点为聊天状态隔离、重复提交、购买流程及异常反馈。

测试使用本机内存数据库和明确标记的测试会员、测试商品，不涉及正式业务数据。工作区同期加入的论坛图片、可读性和导航等改动已保留；本报告的问题清单仅记录本轮负责的修复，最终构建及后端测试基于当时的当前工作区。

## 问题与逐条处理

| 04 | 测试 / P1 | 同一时刻重复调用保存商品、相册、发帖等提交函数，会发出两次写请求 | 在共享业务入口增加同步 busy 检查，保护网页和手机端 | 商品、相册、论坛各自仅发出一次写请求 |

| 06 | 前端 / P2 | 商城或论坛加载失败后重试成功，旧错误仍残留 | 开始新加载时清除旧错误，商城提供明确的重新加载按钮 | 共享逻辑测试及 Web 503 故障注入回归通过 |

| 09 | 产品 / P2 | 搜索无结果误提示商城没商品，关键词前后空格也导致匹配失败 | 独立“无匹配商品”文案、清除筛选入口，关键词去除首尾空格并忽略英文大小写 | Web/H5 搜索、清除、空格关键词检查通过 |
| 10 | 产品 / P2 | 提交成功仅跳转订单列表，后续列表读取失败时用户不易判断是否已经下单 | 保留独立成功提示“订单已提交，等待卖家人工确认”；刷新失败时仍保留该提示，避免误导用户重复下单 | 单元场景覆盖写成功/读失败；Web/H5真实隔离订单均显示成功 |

| 12 | 产品 / P2 | 已取消且未结算订单仍显示“待线下结算”，状态含义矛盾 | 两端统一显示“已取消，无需结算”，已退款订单继续保留退款状态 | Web 真实取消订单后文案断言通过 |
