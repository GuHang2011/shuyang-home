# v2.0.1 上线复查与问题修复

检查日期：2026-11-16。基于 v2.0.0 复查，下面列出本轮确认的问题、修复和验证；未将所有历史测试当作本轮新发现。

## 问题与修复

| 编号 | 影响 | 复现条件 | 修复结果 |
| --- | --- | --- | --- |
| 1 | 联系方式隐私 | 双方已交换联系方式，随后任一方拉黑；或对方被停用、审核状态不再通过，再读取历史交换记录 | 接口每次读取重新检查双方状态及双向拉黑，仅保留查看者自己的联系方式；对方字段被隐藏时，两端明确提示暂不可用，手机不显示空值复制按钮 |
| 2 | 申请权限 | 发出联系申请后发生拉黑，或申请人失去审核资格，接收方仍点击同意 | 同意前重新检查，返回明确拒绝；失败不写入新联系方式，拒绝、取消与撤销仍可使用 |
| 3 | 聊天记录缺失 | 已加载第1–30条，离开期间新增至第130条，最新接口只返回81–130条 | 检测最新页与已加载页间的断层，以最新连续页重置，并恢复“更早消息”分页，能补齐31–80条；连续刷新仍保留已加载历史 |
| 4 | 微信合法文件上传失败 | 从微信选择 PDF／Office 文件，平台临时路径不带原扩展名 | 文件选择保留原名及大小，上传明确传递 originalName；取消选择不触发错误提示 |
| 5 | 退出后仍弹出旧图片 | 点开私有相册照片，下载完成前退出、切换账号、切换相册或离开组件 | 下载响应绑定当前身份及相册，丢弃迟到结果；新点击优先，离开时关闭预览并释放 H5 Blob |
| 6 | 手机下载体积偏大 | 按部署模板启动 Nginx，浏览器支持 gzip，但 JS／CSS 原样传输 | 对公开静态文本启用 gzip；API 的认证 JSON 不在压缩类型中；保留原缓存策略 |
| 7 | 部署验收漏报 | 正式站点 Web 与 H5 混用不同版本，或放入标记为演示的 H5 | 检查两端 release.json 的版本、target、demo:false 和禁止缓存；与包内 VERSION 不一致则失败，可通过 --expected-version 显式指定 |
| 8 | 可兼容修补的依赖告警 | 移动端依赖含四个已有安全补丁的旧版本 | 使用精确旧版本范围的 overrides 修补，锁文件只改变对应包及可复用的嵌套依赖；构建 H5／小程序验证兼容 |

已保存到对方设备的联系方式无法通过撤销追回；本次修复控制后续接口和界面展示。解除拉黑且双方仍符合条件时，原已同意的交换可重新显示；明确撤销的交换不会自动恢复。

压缩实测（当前 Web 构建，支持 gzip 的请求）：主 JS 从874,076字节降至296,455字节，主 CSS 从386,777字节降至64,227字节。测试同时核对解压后的内容等于原文件；这只说明静态传输量下降，不作为真实网络首屏时间或并发容量承诺。

回归脚本可通过 `npm --prefix frontend run test:regression` 运行。生产安装／代理测试只使用临时数据库、临时 HTTPS 证书及本机端口，不读取真实会员库；入口见 `scripts/test-production-runtime.py`、`scripts/test-production-proxy.py`。原始日志与测试截图保存在本地 `.cache` 和 `output`，不提交到仓库。

## 依赖修补及剩余事项

| 包 | 原版本 → 补丁 |
| --- | --- |
| source-map-js | 1.2.1 → 1.2.2，修复不可信 source map 造成资源耗尽 |
| postcss-selector-parser | 6.1.2 → 6.1.5，6.x 安全回补，修复选择器解析资源耗尽 |
| postcss | 仅嵌套的8.5.6 → 8.5.28，复用已存在根版本 |
| ws | 仅8.18.0 → 8.21.0，修复 close 参数内存泄露与碎片消息资源耗尽 |

从官方 npm registry 复核元数据、发布说明／源码差异后，在隔离目录求解锁文件，再落地主工作区安装并构建。`npm audit --omit=dev --registry=https://registry.npmjs.org` 从37项（20 high、10 moderate、7 low）降到32项（17 high、8 moderate、7 low）。计数包含传递依赖影响，不能当作独立业务漏洞数量。

剩余告警涉及 Vite／esbuild／Babel 等开发构建路径、Vue SSR、国际化及其传递链。正式包是静态 H5／小程序，不运行开发服务或 SSR，也不接受不可信国际化词典；这些是暴露边界，不等于告警已修复。开发服务绑定127.0.0.1也不能消除所有跨源访问风险。当前 uni 插件精确要求 Vite 5.2.8、Vue 3.4.21，上游 Vue3 标签仍为 alpha；未执行会把 uni 包降到旧框架的 `audit fix --force`。

参考：[source-map-js公告](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)、[selector解析公告](https://github.com/advisories/GHSA-rj75-hqrm-r3gf)、[ws 8.21发布](https://github.com/websockets/ws/releases/tag/8.21.0)、[PostCSS发布](https://github.com/postcss/postcss/releases/tag/8.5.28)。

## 交付与升级

交付包为 `shuyang-home-v2.0.1.zip`，附 ZIP 校验值和逐文件 SHA256SUMS。包内包括后端、Web、H5、小程序开发构建、部署模板、配置生成及检查工具；不含真实数据库、私有配置或通用生产密码。

首次安装按[部署基线](上线准备-v2.0.0.md)执行，命令从包内 VERSION 读取实际版本。已有 v2.0.0 使用相同 JDK 21／H2 2.4，无额外数据迁移：先停机备份数据库和配置，安装新 JAR、Web／H5 文件，更新 Nginx 模板并通过 `nginx -t` 后重载，再启动服务。保留旧静态哈希资源以兼容仍打开的页面。

不要为已有数据库重新生成密码或数据密钥。升级后在新包目录运行：

```bash
python3 tools/check-deployment.py https://自己的域名 --mobile
```
