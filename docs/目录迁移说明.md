# v1.2.1 目录整理

沭阳之家已经是会员与乡情社区项目，旧农业识别项目的目录名称不再适合当前用途。新结构如下：

| 旧目录 | 当前目录 | 用途 |
| --- | --- | --- |
| `CropDiseasesDetection_vue` | `frontend` | Vue 网页、共享逻辑及 uni-app 移动端 |
| `CropDiseasesDetection_springboot` | `backend` | Spring Boot 服务、集成测试与本地数据目录 |

根目录启动入口保持为 `Start-Frontend.ps1` 和 `Start-Backend.ps1`。日常开发、测试、版本同步和打包脚本均使用新目录；Java 包名、服务接口、数据库格式以及交付包内部的 `web`、`backend`、`mobile-h5`、`wechat-dev-build` 布局保持原有约定。

## 已有本地工作副本

全新克隆直接使用新结构。已有工作副本应先停止正在运行的预览、开发和后端服务，提交或备份未提交源码，再更新版本。旧目录下不受 Git 管理的数据库、附件、密钥配置和依赖不会随 Git 更新自动搬迁：

1. 备份本地数据与私有配置。使用默认文件库时，核对旧后端 `data` 目录；若通过环境变量指定外部目录，继续保留原地址。
2. 更新后将需要保留的旧后端运行数据移到 `backend` 对应位置。若新旧目录均存在数据，先确认使用哪一份，不能覆盖合并数据库。
3. 在 `frontend` 与 `frontend/mobile` 分别运行 `npm ci`，重新构建前后端；不要复用旧 `target` 或 `dist`。
4. 更新 IDE、终端工作目录和自行维护的外部脚本，再通过根目录启动入口运行。

本次不会自动移动工作区之外的数据或重启现有服务。回退到旧标签时，同样应恢复与该版本匹配的目录和配置。

`cleanup-manifest.json` 是项目早期清理时的历史路径清单，保留当时的名称，用于追溯，不是当前启动或构建配置。其记录不应被批量改写成新的事实。
